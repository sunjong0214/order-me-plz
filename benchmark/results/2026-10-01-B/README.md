# 평상시 주문 B (2026-10-01 10:55 ~ 11:33)

평상시 저녁 피크(초당 40건, `benchmark/README.md` 2절 "트래픽 목표치")에서 비동기가 치르는 비용을 쟀다. "비동기가 평소에도 빠른가"에 답하는 회차다.

- 조건: 할인 없는 일반 주문, 코드 `b328abf`, 운영과 같은 설정(커넥션 20, 저장 워커 20, 대기 큐 70,000칸, 동기 처리 상한 없음). 회차마다 서버 설정을 액추에이터로 확인
- 부하: open model 초당 40건 15분(36,001건). 워밍업 초당 500건 1분(결과 버림)
- 반복: 방식별 1회(사용자 결정. 처음 계획은 3회). 순서 동기 → 비동기, 회차 사이 5분 휴식(가벼운 부하)
- 통제: 충전기, 부하 전 두 장비 CPU 확인, 노트북 5초 기록. 유효 판정: 데스크톱 CPU 평균 80% 미만·80% 이상 2표본 연속 없음, k6 연결 실패 0.1% 이하

## 2. 해석

- **평상시에는 비동기가 확정을 앞당기지 않는다.** 접수 응답만 빠르고(평균 1.35 vs 4.1ms), 주문이 DB에 확정되기까지는 약 4.3 vs 4.1ms로 같다. 결과를 SSE·폴링으로 받는 시간까지 더하면 사용자에게는 비동기가 더 늦을 수 있다
- 비동기의 이득은 몰리는 순간에만 나온다(`2026-09-30-FLASH`). 포트폴리오에서는 비동기를 "빠른 응답"이 아니라 "순간 유입 흡수"의 근거로만 쓴다
- 이 부하는 서버 용량(약 3,300건/s, `2026-09-30-CAP2`)의 약 1.2%다. 동시에 커밋하는 요청이 거의 없어 커밋이 묶이지 않고 주문당 redo fsync가 2.3–2.4회다(포화에서는 0.3–0.4회)
